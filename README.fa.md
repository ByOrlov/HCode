> Aider (برآورد ~۱۵۰–۲۵۰ مگابایت) و kimi-code (~۲۵۰ مگابایت+) در مرز همان دسته‌بندی وزنی قرار دارند — ترتیب نسبی‌شان درون حاشیه است.

## داستان پیدایش

مانیتور سیستم را باز کردم و وحشت کردم. دو نمونه opencode در حال بلعیدن **۱ گیگابایت RAM** بودند. پنج چت kimi-code همین‌کار را می‌کردند — چون هرکدام یک زمان اجرای کامل Node.js را با خود کش می‌آوردند.

به ۲۰۰۷ یادم آمد. مادرم برایم **۵۱۲ مگابایت RAM** خرید تا بتوانم *S.T.A.L.K.E.R.: Shadow of Chernobyl* را بازی کنم — یک بازی سه‌بعدی کامل که روی ماشینی با ۱ گیگابایت RAM اجرا می‌شد. و حالا، در ۲۰۲۶، نمی‌توانیم دو چت را روی ۱ گیگابایت اجرا کنیم. چه؟ **دنیا دیوانه شده است.**

بدتر — به این «چت‌ها» سخت است **نرم‌افزار واقعی** بگوییم. این‌ها نمونه‌های اولیه نرم‌افزاری هستند که قابلیت‌هایی به آن‌ها پیچ خورده. نرم‌افزار واقعی نمی‌تواند از نظر کارایی این‌قدر وحشتناک باشد. و ترسناک‌ترین بخش: آن‌ها **نمونه‌های اولیه ابدی** هستند. راه‌حل‌های موقتی ابدی، که به‌عنوان محصول تمام‌شده تحویل داده می‌شوند.

سپس توسعه‌دهندگان دیگر برای ساختن عامل‌ها به Rust پناه می‌برند. Rust زبانی است که در آن به‌جای ساختن چیزها با کامپایلر می‌جنگید — نقطه مقابل. و ضربه نهایی: رقبای Rust در حالت بیکار در **~۱۰× حافظه HCode** می‌نشینند.

پس عامل TypeScript شرکت Moonshot-AI را به‌عنوان پایه گرفتم و منطق آن را با کمک Kimi ۲.۶ و GLM ۵ در Crystal بازنویسی کردم. نخستین نتایج: **~۳ مگابایت بیکار** در برابر ~۲۰۰ مگابایت kimi-code. حلقه اصلی از قبل کار می‌کرد. مصرف اوج بعد از آن بالا رفت — تا ~۱۳۰ مگابایت — که برای یک چت-دفترچه وحشتناک است، اما باز هم کمتر از kimi-code در حالت بیکار است.

**این شکاف همان چیزی است که HCode برای بستن آن وجود دارد.**

## چرا وجود دارد

پنج عامل کدنویسی را به‌صورت موازی راه‌اندازی کنید. RAM خود را ببینید. هر عاملی که زمان اجرای Node.js را همراه خود دارد، بهای آن را می‌پردازد — به ازای هر فرآیند، برای همیشه. هر فرآیند HCode در انتظار اعلان بعدی حدود **۳ مگابایت مقیم** می‌ماند — نه ۱۲۰، نه ۲۵۰، نه ۴۰۰ مگابایت. ویرایشگر شما بودجه حافظه خود را حفظ می‌کند. لپ‌تاپ شما خنک می‌ماند. سیستم‌عامل از swap کردن دست می‌کشد. بالاخره می‌توانید دسته‌ای از عامل‌ها را روی همان ماشینی که دارید اجرا کنید.

> عامل‌های Rust — Codex، grok-build، Goose — هم بومی و سبک هستند. در برابر آن‌ها برتری HCode RAM نیست، بلکه **خوانایی و پروانه** است. [منظره](#منظره) را در ادامه ببینید.

## چرا Crystal؟

ما Rust، Go و TypeScript را با دقت بررسی کردیم. هرکدام ما را به مصالحه‌ای وادار می‌کرد که نمی‌خواستیم با آن زندگی کنیم. Crystal نخستین زبانی بود که به ما اجازه داد هر سه پیروزی را هم‌زمان حفظ کنیم.

- 🦀 **به اندازه Rust امن، با نحوی که یک انسان بتواند بخواند.** تایپ ایستا، امنیت در برابر nil، انواع union، جنریک‌ها و یک سیستم ماکرو — اما کد مانند Ruby خوانده می‌شود و مانند C اجرا. بدون borrow checker که هر بازنویسی را به یک مسئله پژوهشی تبدیل کند. دو عامل بومی پرسر‌وصداتر — **Codex** از OpenAI و **grok-build** از xAI — هر دو به Rust نوشته شده‌اند، و سورس آن‌ها این هزینه را ثابت می‌کند: سریع و امن، اما افزودن یک ابزار یعنی یک هفته جنگیدن با lifetimeها. لایه ابزار Crystal یک فایل است که در یک بعدازظهر می‌خوانید.
- 🐹 **به اندازه Go سبک، بدون کدهای تکراری.** fiberها و کانال‌ها به سبک CSP، کامپایل زیر یک ثانیه، باینری‌های استاتیک تک‌فایلی — اما بدون `if err != nil` در هر خط دیگر. شما قابلیت را می‌نویسید، نه تشریفات را.
- 🟦 **به اندازه TypeScript توانمند، بدون زمان اجرای Node.js به ازای هر فرآیند.** Crystal به‌صورت ahead-of-time به یک باینری بومی LLVM کامپایل می‌شود. هیچ heap از V8، هیچ گرم‌شدن JIT، هیچ حلقه رویداد تکراری درون هر عامل وجود ندارد. کپی حافظه کمتر، انجماد سیستم کمتر، راه‌اندازی سرد به میلی‌ثانیه.

**یک زبان. سه پیروزی. بدون زمان اجرا.**

## کامپایل از سورس

اگر ترجیح می‌دهید HCode را خودتان کامپایل کنید، به Crystal ≥ 1.14 نیاز دارید:

```sh
# Install Crystal ≥ 1.14 — https://crystal-lang.org/install/
brew install crystal          # macOS
# sudo pacman -S crystal      # Arch
# see docs for Debian/Ubuntu/Windows

# Build
git clone https://github.com/ByOrlov/HCode
cd HCode
shards install
rake build            # → ./hcode (release flags)

# Smoke-test your credentials
./hcode --hi

# Headless — one-shot prompt, streams to stdout
./hcode -p "explain this repo's entry point"

# Interactive TUI
./hcode
```
