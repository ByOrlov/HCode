# Тест-кейсы для отрисовки зон (LogZone + ActiveZone)

> После рефактора `plans/just_remove_blanks.md` активная зона **не хранит**
> blank-строки. Освободившиеся строки очищаются ANSI-командами (`\e[2K` /
> `\e[J`), а `TerminalMock` отрезает trailing пустые строки из `visible_rows`.

## Абстракции

### TerminalPort

Интерфейс терминала, через который зоны общаются с экраном:

```
interface TerminalPort
  # Курсор / позиционирование
  def cursor_down(n)    # сдвинуть курсор вниз на n строк (без скролла)
  def cursor_up(n)      # сдвинуть курсор вверх на n строк
  def carriage_return   # курсор в начало строки (\r)
  def clear_below       # очистить текущую строку от курсора и всё ниже (\e[J)

  # Запись
  def clear_line        # очистить текущую строку (\e[2K)
  def write(str)        # записать строку в позиции курсора
  def newline           # \r\n — перевод строки (вызывает скролл, если курсор внизу)

  # Геометрия
  def rows : Int32      # высота терминала
end
```

### TerminalMock

Тестовая реализация `TerminalPort`. Моделирует фиксированный экран `@rows` ×
`@cols`, естественный скролл при `newline` на нижней строке и хранит
`@scrollback` для ушедших вверх строк.

- `screen` — видимая сетка (включая очищенные строки).
- `visible_rows` — `scrollback + screen`, но trailing пустые строки отрезаны.
  Это логическое состояние экрана, против которого проверяются тесты.
- `output` — алиас на `visible_rows`.

### ActiveZone

Stateless-рендерер transient-региона внизу экрана.

- Рисует строки с текущей позиции курсора.
- Если `active_lines.size > available_rows`, рисуется **хвост** зоны
  (последние `available_rows` строк), чтобы редактор/футер всегда были видны.
- После отрисовки, если `prev_visible > visible`, вызывается `clear_below`,
  чтобы стереть остаток предыдущего кадра.
- Не хранит `height_log`, `trailing_blanks`, `consume_blank` и т.п.

### LogZone

Append-only эмиттер финализированных строк. Поддерживает `reveal_limit`,
который ограничивает количество новых строк за кадр:

```
chunk = rows - active_lines.size  # минимум 1
```

Это гарантирует, что одна порция новых log-строк вместе с активной зоной
помещается в viewport без принудительного скролла. Большой буфер дренируется
за несколько кадров.

### Соглашения для массивов

- `L1`, `L2`, … — строки, отправленные в LogZone.
- `A1`, `A2`, … — строки активной зоны.
- Массив показывает финальное состояние `visible_rows` **после** шага.
- `NO_VIEWPORT_ROWS = 100` — высота, при которой `total` никогда не
  превышает `rows`, поэтому `viewport_top` всегда `0`.
- `VIEWPORT_ROWS = 10` — малая высота, активирующая scroll/viewport-логику.

## Тест 0: Пустой LogZone + ActiveZone

Проверяет, что при пустом логе активная зона рисуется с верхней строки.

### Шаг 0.1: log=[L1], active=[A1]

```
→ operations: render_zones(log=[L1], active=[A1])
→ output: [L1, A1]
```

### Шаг 0.2: log=[], active=[A1, A2, A3]

```
→ operations: render_zones(log=[], active=[A1, A2, A3])
→ output: [A1, A2, A3]
```

### Шаг 0.3: log=[], active=[A1] (сжатие с 3 → 1)

```
→ prev: [A1, A2, A3]
→ operations: render_zones(log=[], active=[A1])
→ output: [A1]
```

Строки A2 и A3 очищены `clear_below`; `visible_rows` больше не показывает
пустые строки.

## Тест 1: Итеративные логи + рост/сжатие зоны (без viewport)

### Шаг 1.1: log=[L1..L10], active=[A1]

```
→ output: [L1, L2, L3, L4, L5, L6, L7, L8, L9, L10, A1]
```

### Шаг 1.2: active растёт до [A1, A2]

```
→ output: [L1..L10, A1, A2]
```

### Шаг 1.3: active сжимается до [A1]

```
→ output: [L1..L10, A1]
```

Никакого blank-паддинга — экран сразу уменьшается.

### Шаг 1.4: active растёт до [A1..A10]

```
→ output: [L1..L10, A1..A10]
```

### Шаг 1.5: active сжимается до [A1]

```
→ output: [L1..L10, A1]
```

## Тест 2: Перемежающиеся логи и активная зона (без viewport)

### Шаг 2.1: log=[L1, L2], active=[A1]

```
→ output: [L1, L2, A1]
```

### Шаг 2.2: active растёт до [A1, A2]

```
→ output: [L1, L2, A1, A2]

```
→ output: [L1, L2, L3, A1, A2]

L3 встаёт перед активной зоной; зона перерисовывается внизу.

Экран растёт нормально — trailing blanks больше не поглощаются.

## Тест 3: Viewport (rows=10)

При `rows=10` активная зона прижата к низу viewport; старые логи уходят в
scrollback.

### Шаг 3.1: log=[L1..L5], active=[A1]

```
→ output: [L1, L2, L3, L4, L5, A1]
```

### Шаг 3.2: log растёт до [L1..L15], active=[A1]

Лог дренируется по `chunk = rows - active.size = 9` строк за кадр. В итоге
видимыми остаются последние строки:

```
→ visible[-10..-1]: [L7, L8, L9, L10, L11, L12, L13, L14, L15, A1]
→ scrollback не пуст (L1..L6 ушли вверх)
```

### Шаг 3.3: active растёт до [A1, A2, A3]

```
→ output: [L1..L5, A1, A2, A3]
```

## Тест 4: Tail-clipping активной зоны

Если активная зона выше viewport, рисуется только её хвост.

### Шаг 4.1: log=[L1, L2, L3], active=[D1..D20] (rows=10)

```
→ visible[-10..-1]: [D11, D12, D13, D14, D15, D16, D17, D18, D19, D20]
→ scrollback содержит [L1, L2, L3, D1..D10]
```

### Шаг 4.2: active сжимается до [A1, A2, A3]

`viewport_top` уменьшается → `incremental_render` делает `full_render`:

```
→ output: [L1, L2, L3, A1, A2, A3]
→ screen[6..] пустые (очищены clear_below)
```

## Тест 5: Миграция контента из active в log

Когда финализированный контент переходит из активной зоны в лог, активная
зона просто перерисовывается короче.

### Шаг 5.1: log=[L1, L2], active=[A1, A2, A3]

```
→ output: [L1, L2, A1, A2, A3]
```

### Шаг 5.2: log=[L1..L4], active=[A1, A2]

```
→ output: [L1, L2, L3, L4, A1, A2]
```

## Сводка инвариантов

| № | Инвариант |
|---|-----------|
| 0 | При пустом LogZone активная зона рисуется с ряда 0. |
| 1 | Рост зоны — дорисовка вниз; сжатие — очистка освободившихся строк. |
| 2 | `visible_rows` не содержит trailing пустых строк. |
| 3 | `chunk = rows - active_lines.size` (минимум 1) — throttle для LogZone. |
| 4 | При `total > rows` активная зона прижата к низу viewport; старые логи
    уходят в scrollback. |
| 5 | Если `viewport_top` уменьшается, выполняется полный repaint. |
| 6 | Active zone tail-clips: при превышении `rows` рисуется хвост зоны. |
